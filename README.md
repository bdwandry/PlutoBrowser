# Pluto Browser for Playdate

**Pluto Browser** is a fast, standalone, general-purpose web browser built specifically for the **Playdate handheld console** and **Playdate Simulator** — written in **native C** (no Lua runtime) for maximum performance on device.

Unlike single-purpose feed readers, Pluto Browser lets you navigate to any web address, search the internet, fill out forms, click hyperlinks, and render HTML headings, paragraphs, lists, blockquotes, code blocks, tables, and images (SVG, AVIF, WebP, JPEG, PNG, GIF, BMP, ICO, TIFF, TGA and more) with 1-bit monochrome graphics on the 400x240 sharp LCD screen.

> **Pluto Browser is a port of [CometBrowser](https://github.com/bdwandry/CometBrowser)**, originally written entirely in Lua. It has now been natively ported to C code with Pluto Browser.

> **This project was written entirely with AI.** In fact, every line of code was generated by **GLM 5.3 Flash** and **Muse Spark 1.3** — large language models — working under human direction.

> **V1 of this codebase** (the original Lua-parity C port, merged from `develop_v1_working_on_device`) is preserved at commit `81af638c836c2425480b8a1d25e03a404ff1f5f7`.

> **Current release:** v1.3.3 (build 21), matching `Source/pdxinfo`.

## Building & Sideloading

### 1. Build via Terminal
Requires the [Playdate SDK](https://play.date/dev/) with `PLAYDATE_SDK_PATH` set (or an `SDKRoot` entry in `~/.Playdate/config`).

From the project root, choose one target:

#### 1A) Dual-target bundle (default)
```bash
make
```
Builds `PlutoBrowser.pdx` with both the device binary and the Simulator dylib. Use this for one bundle that works in the Simulator and on the console.

#### 1B) Device-only bundle
```bash
make device
```
Builds a device-only `PlutoBrowser.pdx` with no Simulator dylib. Recommended for sideloading to the console.

#### 1C) Simulator-only bundle
```bash
make simulator
```
Builds a Simulator-only `PlutoBrowser.pdx` for Simulator testing.

Use the Makefile for a full C build; invoking `pdc` on its own only packs an existing tree.

### 2. Run in Playdate Simulator
Double-click `PlutoBrowser.pdx` or open it with the Playdate Simulator app. The bundle must include the Simulator dylib, so use a bundle built with `make` or `make simulator`.

### 3. Sideload to Physical Playdate Console
1. **Via Web Sideload**:
   - Go to [play.date/account/sideload](https://play.date/account/sideload).
   - Zip `PlutoBrowser.pdx` (e.g. `zip -r PlutoBrowser.pdx.zip PlutoBrowser.pdx`) and drag & drop it onto the webpage.
   - On your Playdate, navigate to **Settings > Games > Sideloaded** and download.
2. **Via USB Disk Mode**:
   - Connect Playdate via USB.
   - On device: **Settings > System > Reboot to Data Disk**.
   - Copy `PlutoBrowser.pdx` into the `Games/` directory on the Playdate USB drive.
   - Eject the disk.

For the exact hardware workflow used during development — `pdutil` data-disk mode, deleting and recopying the PDX, verifying the `pdex.bin` MD5 before ejecting, the 60-second relaunch wait, and device log collection — see **AGENTS.md**.

## Key Features

### Navigation & Search
- **Anywhere URL & Search Navigation**: Type any website address or search terms directly.
- **Multiple Search Engines**: DuckDuckGo Lite, FrogFind, Wiby, Wikipedia Search.
- **Full Browsing History**: Back/forward navigation with persistent history (50 entries) stored to disk.
- **Bookmarks**: Save and manage bookmarks, persisted to disk.
- **Default Speed Dial**: 10 pre-loaded bookmarks on the home page (Wikipedia, DuckDuckGo Lite, FrogFind, Wiby and more).

### Rendering
- **JavaScript**: Five selectable engines — muJS, Duktape, QuickJS, XS, and the default XS No-Recursion fork — run page scripts with DOM access and engine-dependent browser APIs such as timers, XHR/fetch, storage/cookies, history/location, modules, and dynamic script loading. Execution modes are **Off**, **Inline**, and **Full** (default); device-safety caps contain runaway scripts. Test coverage: `about:javascript` and `about:jsext`.
- **Browsing modes**: **Reader Mode** extracts the main article; **HTML Mode** renders the full page with links, forms, and a virtual mouse cursor.
- **HTML & inline text**: Headings, paragraphs, lists, tables, links, images, semantic containers, blockquotes, code/pre, details/summary, dialog, fieldsets, ruby, and inline formatting (bold, italic, underline, strikethrough, code, small, sub/sup, alignment). `<base href>` and `<meta http-equiv="refresh">` are honored.
- **CSS**: Type/class/id/attribute and structural selectors, `@media`, `::before`/`::after`, custom properties and `calc()`, box model, borders, table collapse, font-size buckets, wrapping/whitespace, gray dithering, flex rows, sticky app bars, and linearized grid/table layouts for the 1-bit screen. Test coverage: `about:acidtest` and `about:cssprobe`.
- **Forms**: Text inputs, checkboxes, radios, selects, hidden fields, submit/reset buttons, and `<button>`; GET and POST submission (urlencoded/text, with multipart as a documented policy boundary), native constraint validation, and `form.reset()` / `form.submit()` / `form.requestSubmit()`.

### Image Decoding
- **SVG**: Paths including arcs, transforms, viewBox, fills/strokes, gradients, and inline styles.
- **WebP**: VP8 lossy and VP8L lossless stills, including alpha; animated WebP uses the first frame.
- **JPEG**: Baseline and progressive DC decoding with Huffman tables.
- **PNG**: Palette, truecolor, grayscale, and alpha; 1–16-bit and transparency. Adam7 interlaced files decode the first pass only.
- **GIF**: GIF87a/89a first frame; animated GIFs show frame one.
- **BMP**: 1/4/8-bit palette and 24/32-bit truecolor.
- **ICO/CUR**: DIB and PNG-compressed icon entries.
- **AVIF**: 8-bit single-item stills up to 1600px per side through vendored dav1d 1.5.1; the device also refuses frames over 200k pixels. Unsupported 10/12-bit and grid images fall back to a placeholder.
- **Extra formats**: TIFF, TGA, PSD composite, SGI, XBM, and PDF-embedded raster images.
- **Dithering**: 4×4 Bayer ordered dithering to 1-bit.

### Image Rendering Modes
Configurable via **Settings > Image Mode** (Left/Right to cycle). Controls how images are downloaded, cached, and displayed to optimize memory usage and frame rate on the physical Playdate hardware.

| Mode | Behavior |
| :--- | :--- |
| **Render All** (default) | Downloads and renders every image on the page in the background. Full visual fidelity at the cost of memory and initial load time. |
| **In-View Only** | Downloads images only when they scroll into the visible viewport. Automatically evicts (frees) images from memory when they scroll off-screen with a 200px buffer. Best balance of visual quality and memory on device. |
| **On-Demand** | Shows a placeholder card for each image. Tapping an image opens a choice overlay: **(A) View Image** to download and render it, or **(B) Open Link** to follow the hyperlink. Loaded images can be tapped again to **Unload** them from memory. Maximum control over what gets downloaded. |
| **Hover** | Shows a `[Hover]` placeholder until the cursor (HTML mode) or link selector (Reader mode) moves over the image, then temporarily loads and renders it. The image is evicted from memory as soon as the cursor/selection moves away. Good for quick previews without long-term memory cost. |
| **Disabled** | Shows an `[Image Off]` placeholder for every image. No images are downloaded or rendered. Maximum frame rate on physical device for text-heavy browsing. |

### Networking
- **Selectable Network Stack**: **Settings > Network Protocol** cycles **Hybrid** (default — pages, scripts, XHR/fetch and forms ride the raw-TCP stack; display images ride the OS HTTP stack), **TCP** (raw sockets for everything), and **HTTP** (the Playdate OS HTTP stack for everything). `about:` pages are always served locally with no wire request, and the chrome badge shows the live route (`[WEB-TCP]`, `[WEB-HTTP]`, `[WEB-HYBRID]`).
- **HTTP/1.1 over TCP**: Native async sockets with SDK TLS, keep-alive, chunked transfer, connection-pool recovery, and `Accept-Encoding: identity` by default with a gzip fallback (**Settings > Compression**). Redirects are followed with depth tracking and browser-true verb semantics: 301/302/303 rewrite POST→GET and drop the body; 307/308 preserve method, body and Content-Type. Range requests (206) and cache revalidation (`If-None-Match` → 304) are supported.
- **OS HTTP Backend**: Uses `playdate.network.http` for pages or display images when selected; both backends share one in-flight request.
- **Cookie Jar**: Session cookie persistence across requests, also exposed to page scripts through `document.cookie` (on XS No-Recursion).
- **Character Encoding Detection**: Scans `<meta charset>`, `<meta http-equiv="Content-Type">`, BOM markers, and chardet heuristics.

### User Interface
- **Display FPS**: Settings option cycling **30**, **50** (default), or **Uncapped** (0). 50 fps yields smoother scrolling and more responsive crank/cursor motion at the cost of higher battery usage.
- **Show FPS**: Settings option (**Off** default) drawing a live frame-rate overlay.
- **Invert Crank**: Settings option reversing the crank's scroll/cursor direction.
- **JavaScript Execution**: Settings option with three modes (default **Full**, persisted): **Off** — no JS engine is created and scripts are ignored; **Inline** — embedded `<script>` blocks run during page load (HTML mode) and live element click listeners can intercept links; **Full** — external `<script src>` files are also downloaded and executed, browser-faithful: resolved against the page URL, fetched once per unique file via the same single-flight HTTP client, deduplicated but executed at every slot in page order (max 48 script elements, 24 unique external files), with disk-streamed downloads uncapped, a 512KB RAM-resident per-page budget, a 768KB per-script execution ceiling, and fail-skip so one bad file never breaks the page. (Replaces the earlier On/Off "Enable Javascript" toggle; previously saved values carry over.)
- **JavaScript Engine**: Settings row selecting the active JS engine — cycles **muJS ↔ Duktape ↔ QuickJS ↔ XS (Moddable) ↔ XS (No Recursion)** (persisted, default **XS (No Recursion)**) when Execution is Inline or Full, and locks to **Off** when Execution is Off (derived from the Execution policy — it can never disagree with it). Strict engine isolation: the selected engine runs the page exclusively (all inline and external scripts, listeners, `document.write`, click dispatch); the other engines' code is never entered — no mixing, no fallback. The four stock engines are vendored and never modified: muJS 1.3.10 (ES5 subset), Duktape 2.7.0 (ES5.1), QuickJS 2026-06-04 (ES2023, same DOM surface), and XS (Moddable). The XS No-Recursion fork is the project's own no-recursion port of XS.
- **Compression**: Settings option (**Off** default, identity-first requests; **Gzip** sends `Accept-Encoding: gzip` with strict accounting and a transparent fallback).
- **Cached Website**: Settings option (**Off** default) serving snapshot revisits instantly; empty/loading renders are never cached.
- **Network Protocol**: Settings option cycling **TCP → HTTP → Hybrid** (persisted, default **Hybrid**) — see Networking above.
- **Clock Format**: Settings option (**12-Hour** default, **24-Hour** alternative) for the chrome-bar clock and history timestamps — always live device-local time, following travel and daylight-saving changes with no restart.
- **Chrome Bar**: host/URL display, SSL lock icon, loading progress, local-time clock, WiFi indicator, and the live `[READER-…]` / `[WEB-…]` network-protocol badge.
- **Address Bar**: On-screen keyboard for URL entry and search.
- **URL Hover Status Bar**: Shows destination URL when hovering links in HTML mode (like desktop browsers).
- **Link Preview**: Bottom HUD displays `-> https://...` for D-pad-selected links in reader mode.
- **Scrollbar**: Visual scrollbar with thumb position indicator.
- **Error Page**: Retry / Search / Home options on load failure.
- **Reader Mode Toggle**: Switch between article-distilled reader and full HTML rendering through **Settings > Browse Mode** (the system menu's three slots vary by page; Settings is always one).

### Internal Pages

All internal pages are available from the address bar and as **Test Cases** cards on the Home page. Each probe paints pass/fail rows on the page and writes receipts to `pluto.log`; closing summaries include `apifetch:`, `apihist:`, `apicon:`, `formsum:`, and `netsum:`.

| Page | What it tests |
| :--- | :--- |
| `about:home` | Speed Dial start page. |
| `about:blank` | Blank page. |
| `about:acidtest` | HTML, CSS, layout, and image rendering suite. |
| `about:javascript` | JavaScript engine and DOM integration (PASS/PART/MISS per capability). |
| `about:jsext` | External `<script src>` / Full-mode loading, including `animationend`/`transitionend` delivery. |
| `about:cssprobe` | Zero-JS CSS engine probe: selectors, `@media`, flex/grid, `var()`/`calc()`, generated content, animations, and unit/transform grammar. |
| `about:apiprobe` | Browser-API battery: events, fetch/XHR, timers, web storage, history/location, console, modules, templates, and DOM conveniences. |
| `about:formprobe` | Forms battery: field read/write, checkbox/radio/select, focus/blur, form APIs, constraint validation, plus device-policy rows (no file picker, no date/range/color widgets, one-line multi-row select). |
| `about:formval` | Native validation demo using `required`, `min`/`max`, and `:valid`/`:invalid` styling. |
| `about:netprobe` | Network battery: 4 local rows in every build; 17 wire rows only with `PLUTO_NETLAB_ON` against `tests/netlab_server.py` (ship builds report `SKIP`). Covers caching, gzip, chunked, 404, headers, cookies, redirects, 304, ranges, and timeout. |

All 10 user-facing internal pages are also listed **on the Home page** under a **Test Cases** section beneath Speed Dial: each built-in `about:` page gets a clickable card (identical card grid and crank/D-pad navigation as bookmarks; A opens the page). The `about:p5m0`/`about:p5m1` module fixtures are import-only and deliberately omitted.
