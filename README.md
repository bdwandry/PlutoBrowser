# Pluto Browser for Playdate

**Pluto Browser** is a fast, standalone, general-purpose web browser built specifically for the **Playdate handheld console** and **Playdate Simulator** — written in **native C** for maximum performance on device.

Unlike single-purpose feed readers, Pluto Browser lets you navigate to any web address, search the internet, fill out forms, click hyperlinks, and render HTML headings, paragraphs, lists, blockquotes, code blocks, tables, and images (SVG, WebP, JPEG, PNG, GIF, BMP, ICO, TIFF, TGA and more) with 1-bit monochrome graphics on the 400x240 sharp LCD screen.

> **Pluto Browser is a port of [CometBrowser](https://github.com/bdwandry/CometBrowser)**, originally written entirely in Lua. It has now been natively ported to C code with Pluto Browser.

> **This project was written entirely with AI.** In fact, every line of code was generated by **GLM 5.3 Flash** and **Muse Spark 1.3** — large language models — working under human direction.

> **V1 of this codebase** (the original Lua-parity C port, merged from `develop_v1_working_on_device`) is preserved at commit `81af638c836c2425480b8a1d25e03a404ff1f5f7`.

## Key Features

### Navigation & Search
- **Anywhere URL & Search Navigation**: Type any website address or search terms directly.
- **Multiple Search Engines**: DuckDuckGo Lite, FrogFind, Wiby, Wikipedia Search.
- **Full Browsing History**: Back/forward navigation with persistent history (50 entries) stored to disk.
- **Bookmarks**: Save and manage bookmarks, persisted to disk.
- **Default Speed Dial**: 10 pre-loaded bookmarks on the home page (Wikipedia, DuckDuckGo Lite, FrogFind, Wiby and more).

### Rendering
- **JavaScript Engines (default XS-NoRecursion)**: Real script execution wired into the DOM pipeline, toggled via **Settings > JavaScript Execution** (default **Full**). Five vendored stock engines run pages exclusively (Settings cycles **muJS ↔ Duktape ↔ QuickJS ↔ XS (Moddable) ↔ XS (No Recursion)**): muJS 1.3.10, Duktape 2.7.0 (ES5-class), QuickJS 2026-06-04 (ES2023, same DOM surface), and XS with time-sliced bundle evaluation, stepwise parsing, and resumable mounts for deep pages on the 61.8KB game-task stack. Pages can read and mutate the live DOM (`getElementById`, `textContent`, `setAttribute`, `createElement`/`appendChild`/`removeChild`, element `click` listeners with `preventDefault`), use `document.write` during load, fire `setTimeout`/`setInterval` timers between frames, and fetch (`XMLHttpRequest` GET, `fetch` on QuickJS). Hard device-safety limits: instruction run-limit per event, DOM-call budget per page, per-script size cap, and bounded `document.write` capture (runaway scripts are contained, never lock the browser). Test the engine at `about:javascript`.
- **Dual Browsing Modes**:
  - **Reader Mode**: Distills articles for clean, distraction-free reading.
  - **HTML Mode**: Full visual layout with virtual mouse cursor, interactive forms, and clickable elements.
- **HTML Elements**: `<html>`/`<head>`/`<body>`, `<h1>`-`<h6>`, `<p>`, `<div>`/`<span>`, `<a>`, `<ul>`/`<ol>`/`<li>`, semantic containers (`<article>`/`<section>`/`<nav>`/`<header>`/`<footer>`/`<main>`/`<figure>`), `<blockquote>`, `<code>`, `<pre>`, `<hr>`, `<br>`/`<wbr>`/`<nobr>`, `<img>`, `<table>`, `<details>`/`<summary>`, `<dialog>`, `<fieldset>`, `<select>`, ruby, text-level semantics, and `<script>` blocks (Inline mode runs embedded scripts; Full mode additionally downloads and runs `src=` files in page order; Off skips scripts entirely). Script pages show an honest `Loading...` state while content arrives.
- **CSS Engine**: Selectors (child `>`, `:first/last/only/nth-child`, `:link`, `[attr]`, `!important`), `@media` (width/height, print, monochrome, orientation), `::before`/`::after` with `content`/`attr()`, borders, box spacing, tables with `border-collapse`, dithered grays, font-size buckets, `white-space`/`break-word`, and `display` mapping (flex/grid/table linearize for 1-bit). Covered by `about:acidtest`; the deeper engine canaries (keyframes registry, animationend/transitionend lanes, the P9 unit/transform grammar, probe census rows) render at `about:cssprobe`.
- **Form Support**: Text inputs, checkboxes, radio buttons, dropdowns, submit buttons, hidden fields, and `<button>` elements. Forms are submitted per the HTML spec (hidden inputs included, submit button name/value always appended), and GET submissions navigate browser-style: the query string is ONE form data set (`user=Pluto&age=` — the typed values once, the submitter's pair only through a real button activation, empty controls still serialize, enctype never picks the GET shape; `action` URLs that already carry a query join with `&`; `method="dialog"` closes the page without navigating — the spec's "otherwise not submit" hold, receipts a no-op when the form has no ancestor `<dialog>`). POST encodings select honestly: `application/x-www-form-urlencoded` (the wire), `text/plain` (raw CRLF `name=value` pairs per spec; GET ignores the enctype like a browser), and `multipart/form-data` stays a documented policy boundary (the POST still rides the urlencoded wire with a loud log saying so). The form element also reflects the submission state on every engine: `form.method` / `form.enctype` / `form.encoding` (alias) read the browser's lowcased known values with GET / urlencoded defaults for missing-or-invalid attributes and write the string verbatim. Native constraint validation gates submit attempts (`required`/`pattern`/`min`/`max`/`minlength`/`maxlength`/type; `novalidate`/`formNovalidate` skip) with `invalid` events and the `validity`/`validationMessage`/`willValidate`/`checkValidity()`/`reportValidity()` surface on every engine; stylesheets can style `:required`/`:optional`/`:valid`/`:invalid`. The form element carries the submit API on every engine: `form.elements` (live controls collection), `form.reset()` restoring walk-time defaults (typed values revert to the `value` attributes, focused item included), `form.submit()` (no validation — straight to the wire) versus `form.requestSubmit()` (the native gate runs first, exactly like the real button), implicit Enter submit on non-textarea fields riding the first submit button in tree order, and `el.click()` on submit/reset buttons (`event.submitter` stays a documented boundary). `FormData` is real on every engine: `new FormData(form[, submitter])` (or bare, an EMPTY instance) reads one bridge-owned fixed store, with `append`/`get`/`getAll`/`has`/`set`/`delete`/`forEach`/`entries`/`keys`/`values` + iterators — and the submit wire serializes its POST body from THE SAME collector, so the JS-side FormData pairs and the actual submitted body agree byte-for-byte (the `about:formprobe` parity row).
- **Inline Styles**: Bold, italic, underline, strikethrough, code, small, sub/superscript, text alignment.
- **`<base href>` Support**: Resolves relative URLs correctly when a base element is present.
- **Meta Refresh Redirect**: Automatically follows `<meta http-equiv="refresh">` redirects after the specified delay.

### Image Decoding
- **SVG**: Full path rendering (M, L, H, V, C, S, T, A, Z commands), transforms, viewBox, CSS styles.
- **WebP (VP8)**: Lossy and lossless sub-images, full image decoding pipeline.
- **JPEG**: Baseline DCT decoding with Huffman tables.
- **PNG**: Interlaced and non-interlaced, palette and truecolor, transparency.
- **GIF**: Animated and static, frame-by-frame rendering.
- **BMP**: 1-bit and 8-bit bitmaps with palette support.
- **ICO**: Favicon extraction from website icons.
- **Extra Formats**: TIFF, TGA, PSD, SGI, XBM and PDF-embedded image decoding.
- **1-bit Dithering**: Ordered dithering for grayscale-to-monochrome conversion.

### Image Rendering Modes
Configurable via **Settings > Image Mode** (Left/Right to cycle). Controls how images are downloaded, cached, and displayed to optimize memory usage and frame rate on the physical Playdate hardware.

| Mode | Behavior |
| :--- | :--- |
| **Render All** (default) | Downloads and renders every image on the page in the background. Full visual fidelity at the cost of memory and initial load time. |
| **In-View Only** | Downloads images only when they scroll into the visible viewport. Automatically evicts (frees) images from memory when they scroll off-screen with a 200px buffer. Best balance of visual quality and memory on device. |
| **On-Demand** | Shows a placeholder card for each image. Tapping an image opens a choice overlay: **(A) View Image** to download and render it, or **(B) Open Link** to follow the hyperlink. Loaded images can be tapped again to **Unload** them from memory. Maximum control over what gets downloaded. |
| **Hover** | Shows a `[Hover]` placeholder until the cursor (HTML mode) or link selector (Reader mode) moves over the image, then temporarily loads and renders it. The image is evicted from memory as soon as the cursor/selection moves away. Good for quick previews without long-term memory cost. |
| **Disabled** | Shows an `[Image Off]` placeholder for every image. No images are downloaded or rendered. Maximum frame rate on physical device for text-heavy browsing. |

### Networking
- **Dual-Engine HTTP/HTTPS**: Native async socket communication over raw TCP with SDK TLS, HTTP/1.1 keep-alive, redirect following with depth tracking, and `Accept-Encoding: identity` by default with a gzip fallback (**Settings > Compression**).
- **HTTP Redirect Handling**: Follows 301/302 redirects with depth tracking.
- **Chunked Transfer**: Supports chunked transfer-encoding.
- **Cookie Jar**: Session cookie persistence across requests.
- **Character Encoding Detection**: Scans `<meta charset>`, `<meta http-equiv="Content-Type">`, BOM markers, and chardet heuristics.

### User Interface
- **Display FPS**: Settings option with **50** (default), **30**, or **0-Uncapped**. 50 fps yields smoother scrolling and more responsive crank/cursor motion at the cost of higher battery usage.
- **JavaScript Execution**: Settings option with three modes (default **Full**, persisted): **Off** — no JS engine is created and scripts are ignored; **Inline** — embedded `<script>` blocks run during page load (HTML mode) and live element click listeners can intercept links; **Full** — external `<script src>` files are also downloaded and executed, browser-faithful: resolved against the page URL, fetched once per unique file via the same single-flight HTTP client, deduplicated but executed at every slot in page order (max 48 script elements, 24 unique external files), with disk-streamed downloads uncapped, a 512KB RAM-resident per-page budget, a 768KB per-script execution ceiling, and fail-skip so one bad file never breaks the page. (Replaces the earlier On/Off "Enable Javascript" toggle; previously saved values carry over.)
- **JavaScript Engine**: Settings row selecting the active JS engine — cycles **muJS ↔ Duktape ↔ QuickJS ↔ XS (Moddable) ↔ XS (No Recursion)** (persisted, default **XS (No Recursion)**) when Execution is Inline or Full, and locks to **Off** when Execution is Off (derived from the Execution policy — it can never disagree with it). Strict engine isolation: the selected engine runs the page exclusively (all inline and external scripts, listeners, `document.write`, click dispatch); the other engines' code is never entered — no mixing, no fallback. All engines are vendored stock and never modified: muJS 1.3.10 (ES5 subset), Duktape 2.7.0 (ES5.1), QuickJS 2026-06-04 (ES2023 with the same browser DOM surface).
- **Compression**: Settings option (**Off** default, identity-first requests; **Gzip** sends `Accept-Encoding: gzip` with strict accounting and a transparent fallback).
- **Cached Website**: Settings option (**Off** default) serving snapshot revisits instantly; empty/loading renders are never cached.
- **Clock Format**: Settings option (**12-Hour** default, **24-Hour** alternative) for the chrome-bar clock and history timestamps — always live device-local time, following travel and daylight-saving changes with no restart.
- **Chrome Bar**: URL display, SSL lock icon, page title, loading progress, local-time clock, WiFi indicator, battery level, reader/HTML mode toggle.
- **Address Bar**: On-screen keyboard for URL entry and search.
- **URL Hover Status Bar**: Shows destination URL when hovering links in HTML mode (like desktop browsers).
- **Link Preview**: Bottom HUD displays `-> https://...` for D-pad-selected links in reader mode.
- **Scrollbar**: Visual scrollbar with thumb position indicator.
- **Error Page**: Retry / Search / Home options on load failure.
- **Reader Mode Toggle**: Switch between article-distilled reader and full HTML rendering from the system menu.

## Building & Sideloading

### 1. Build via Terminal
Requires the [Playdate SDK](https://play.date/dev/) with `PLAYDATE_SDK_PATH` set (or an `SDKRoot` entry in `~/.Playdate/config`).

From the project root:
```bash
make
```
Or directly using `pdc`:
```bash
pdc Source PlutoBrowser.pdx
```

### 1b. Device-only production build (`make device`)
```bash
make device
```
Ships a **device-only** `PlutoBrowser.pdx` (`pdex.bin` + assets, no simulator dylib inside — a leftover sim dylib from an earlier `make` cannot survive in the bundle). Side-load this bundle to the console (section 3).

All 230 device objects — app code, all four JS engines (muJS, Duktape, QuickJS shim, stock XS), the XS No-Recursion fork, dav1d, and the whole browser pipeline — compile at **`-O3` by default** (device receipts 2026-10-22: real-site full cycle + 5-page internal battery, zero crashlog; stack-usage audit ≤ +48B per frame). The simulator build never reads this flag and stays unchanged.

Rollback valve (per build, no file edits):
```bash
make device DEVICEOPT=-O2
```

### 2. Run in Playdate Simulator
```bash
make simulator
```
Or double-click `PlutoBrowser.pdx` or open it with the Simulator app.

### 3. Sideload to Physical Playdate Console
1. **Via Web Sideload**:
   - Go to [play.date/account/sideload](https://play.date/account/sideload).
   - Zip `PlutoBrowser.pdx` (e.g. `zip -r PlutoBrowser.pdx.zip PlutoBrowser.pdx`) and drag & drop it onto the webpage.
   - On your Playdate, navigate to **Settings > Games > Sideloaded** and download.
2. **Via USB Disk Mode**:
   - Connect Playdate via USB.
   - On device: **Settings > System > Reboot to Data Disk**.
   - Copy `PlutoBrowser.pdx` into the `Games/` directory on the Playdate USB drive.
   - Eject the disk.
